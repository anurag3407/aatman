# Configuration

## Sources of configuration

| Context | File | Committed? |
|---|---|---|
| Local development | `.env.local` (generated by `pnpm setup:env`) | No |
| Template for local | `.env.example` | Yes |
| VPS production | `/opt/aatman/shared/.env` (generated by `deploy/scripts/init-env.sh`) | No |
| Template for production | `deploy/.env.example` | Yes |
| Render | Environment variables in the Render dashboard / `render.yaml` | Blueprint yes, secrets no |
| Tests | Hardcoded in `vitest.config.ts` and `playwright.config.ts` | Yes (test keys only) |

`src/lib/env.ts` validates the application variables once and caches the result. Empty strings
are treated as unset, so template lines like `KEY=` are safe.

## Local setup

```bash
pnpm install
pnpm setup:env      # writes .env.local with random secrets; never overwrites
pnpm dev            # http://localhost:3000
```

`setup:env` generates:

- `SESSION_SECRET` — 48 random bytes, base64
- `PSEUDONYM_KEY` — 48 random bytes, base64
- `DATA_ENCRYPTION_KEY` — 32 random bytes, base64
- `CRON_SECRET` — 32 random bytes, hex
- `DEV_LOGIN=true`
- `COUNSELLOR_EMAILS=counsellor@nitp.ac.in`
- `ADMIN_EMAILS=admin@nitp.ac.in`

The database defaults to `pglite:./.data/pglite`, which needs no server and auto-migrates.

Dev sign-in:

| Email | Role |
|---|---|
| any `@nitp.ac.in` | student |
| `counsellor@nitp.ac.in` | counsellor |
| `admin@nitp.ac.in` | admin |

## Application variables

### Core

| Variable | Required | Default | Validation / notes |
|---|---|---|---|
| `NODE_ENV` | no | `development` | `development` / `test` / `production` |
| `APP_URL` | no | `http://localhost:3000` | Valid URL; used for OAuth redirects, same-origin checks, alert links |
| `DATABASE_URL` | no | `pglite:./.data/pglite` | `postgres://…` in production; `pglite:memory` or `pglite:<dir>` locally |
| `DATABASE_POOL_MAX` | no | `10` | 1–100; per replica |
| `RETENTION_MONTHS` | no | `12` | 1–60 |
| `ALLOW_PGLITE_IN_PRODUCTION` | no | unset | Read directly (not in zod schema); must be `"true"` to allow PGlite in production for e2e |

### Secrets

| Variable | Required | Validation | Loss impact |
|---|---|---|---|
| `SESSION_SECRET` | **yes** | ≥ 32 chars | All sessions invalid; safe to rotate |
| `PSEUDONYM_KEY` | **yes** | ≥ 32 chars | Accounts orphaned; avoid rotation |
| `DATA_ENCRYPTION_KEY` | **yes** | base64 of exactly 32 bytes | Encrypted content unreadable |
| `CRON_SECRET` | production **yes** | ≥ 32 chars (optional locally) | Cron endpoints return 401 |

Generate:

```bash
openssl rand -base64 48   # SESSION_SECRET, PSEUDONYM_KEY
openssl rand -base64 32   # DATA_ENCRYPTION_KEY
openssl rand -hex 32      # CRON_SECRET
```

| `CLINICAL_LEAD_EMAILS` | recommended | Escalation level 2; falls back to `ALERT_EMAILS` |
| `NOTIFY_WEBHOOK_URL` | production required | Receives `POST { to, subject, text }` |

The staff alerts page warns about this.

### Development

| Variable | Required | Notes |
|---|---|---|
| `DEV_LOGIN` | no | `true` enables dev sign-in only outside production |

Production gates in `env()`:

- `DEV_LOGIN` must be false.
- `LLM_PROVIDER` must not be `mock`.
- `DATABASE_URL` must not be `pglite:*` unless `ALLOW_PGLITE_IN_PRODUCTION=true`.
- `CRON_SECRET` must be set.
- Google or Microsoft SSO must be configured.

Any violation throws at first `env()` call, so the app fails fast instead of running degraded.

## Environment file precedence

Next.js loads `.env.local` over `.env` in development. The Docker image does not copy
`.env.local`; Compose passes `env_file: .env` (a symlink to `/opt/aatman/shared/.env`) and
explicit `environment:` values.

`scripts/start.sh`:

```sh
if DATABASE_URL is postgres://:
  node scripts/migrate.mjs
exec node server.js
```

PGlite databases migrate themselves on connect, so the script skips them.

## Production settings checklist

- [ ] `APP_URL` exactly `https://$DOMAIN`
- [ ] `DOMAIN` is not an example value
- [ ] `DEV_LOGIN=false`
- [ ] `SESSION_SECRET`, `PSEUDONYM_KEY`, `DATA_ENCRYPTION_KEY`, `CRON_SECRET` set and backed up
- [ ] `DATA_ENCRYPTION_KEY` decodes to 32 bytes
- [ ] `ALLOWED_EMAIL_DOMAINS` correct
- [ ] Google or Microsoft SSO configured; redirect URIs registered
- [ ] `COUNSELLOR_EMAILS` and `ADMIN_EMAILS` populated
- [ ] `ALERT_EMAILS` and `CLINICAL_LEAD_EMAILS` populated
- [ ] `NOTIFY_WEBHOOK_URL` configured and tested
- [ ] `LLM_PROVIDER` intentionally chosen; not `mock`
- [ ] `RETENTION_MONTHS` matches the privacy notice
- [ ] `HOSTEL_NAMES` populated for chat scrubbing
- [ ] Database pool × replicas below `PG_MAX_CONNECTIONS`
- [ ] Backups configured, off-server copies verified
- [ ] Cron container running; retention and alerts observed

`release.sh` enforces a subset (required keys, `APP_URL`, non-example domain, SSO, dev login).

## Key rotation

| Key | Procedure |
|---|---|
| `SESSION_SECRET` | Replace; all users sign in again. No data migration. |
| `CRON_SECRET` | Replace in app env and scheduler together. |
| SSO secret | Rotate in IdP and app; brief login outage. |
| `PSEUDONYM_KEY` | **Avoid.** Requires re-linking every account; no tooling exists. |
| `DATA_ENCRYPTION_KEY` | Requires `v2` ciphertext support and a re-encryption backfill; not implemented. |

## Render configuration

`render.yaml` defines a Docker web service:

- region `singapore`
- free plan
- health check `/api/health`
- `autoDeploy: true`
- `APP_URL=https://aatman.sayalabs.in`
- `ALLOWED_EMAIL_DOMAINS=nitp.ac.in,sayalabs.in`
- Google SSO placeholders
- `LLM_PROVIDER=openai_compat` with a River.ai base URL and model
- secrets marked `sync: false`

Caveats:

- No scheduler is defined for cron; retention/alerts will not run unless added externally.
- Free plan sleeps; expect cold starts.
- `PSEUDONYM_KEY` and `SESSION_SECRET` use `generateValue: true`; `DATA_ENCRYPTION_KEY` is a
  manual 32-byte base64 secret.
- Redis/worker services are not part of the blueprint.

## Troubleshooting configuration

| Symptom | Cause |
|---|---|
| `Invalid environment configuration` on boot | Missing/short secret, bad URL, empty domains, wrong key size |
| `Unsafe production configuration` | Dev login, mock LLM, PGlite, missing cron secret, no SSO |
| OAuth `redirect_uri_mismatch` | IdP registration does not match host/`APP_URL` callback |
| `bad_origin` on mutations | `APP_URL` origin differs from the browser origin/proxy host |
| Alerts page says nobody will be paged | `NOTIFY_WEBHOOK_URL` unset in production |
| Chat says unavailable | `LLM_PROVIDER=none` or misconfigured provider |
| Reminders never send | `SMS_WEBHOOK_URL` unset, or no opt-in/phone |
| Dev login 404 | `DEV_LOGIN` false or production |
| Rate limits feel global | Keys are per pseudonym; shared IPs are not the key |
| PGlite error in production | `ALLOW_PGLITE_IN_PRODUCTION` not `true` (should only be e2e) |
